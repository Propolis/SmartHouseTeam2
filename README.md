### Пошаговое объяснение с конкретными деталями и важным контекстом

## **О проекте**

### Веб-интерфейс, который позволяет удаленно управлять системой «Умный дом» и отслеживать текущее состояние всех ключевых компонентов.
#### Взаимодействие фронтенда с серверной частью построено по архитектуре клиент-сервер. Бэкенд написан на Flask и реализует REST API, с помощью которого фронтенд отправляет запросы для управления компонентами умного дома  и  мониторинга всех состояний в реальном времени, без необходимости перезагружать страницу. 

### **Стек технологий**
   - **Фронтенд**: *React (SPA)  + Nginx (раздача статических файлов).*
   - **Бэкенд**:  *Flask (REST API) + Gunicorn (WSGI-сервер) + MQTT (взаимодействие с IoT устройствами).*
   - **Инфраструктура**:  *Docker Compose, Nginx (reverse proxy).*



##  **Установка и запуск**

   - **Шаг 1**:  Добавьте в переменные файла `.env` свои значения
     ```bash
     MQTT_SERVER=server
     MQTT_PORT=12345
     MQTT_USER=user
     MQTT_PASSWORD=password
     MQTT_TOPICS_MONITORING_CONDITION=Module_1,Module_2,Module_3 
     MQTT_TOKEN_AUTHORIZATION=Token 1234qwerty
     ```
     **MQTT\_TOPICS\_MONITORING\_CONDITION** - список топиков, на которые подписан сервер для мониторинга состояния устройств
   - **Шаг 2** Развертывание проекта: 
     - Убедитесь, что на вашем компьютере установлен  и запущен Docker. Также должен быть установлен Docker Compose:&#x20;
```docker-compose --version```
     - Выполните в корневой директории:
     ```docker-compose up --build -d```

     Это соберет образы и запустит контейнеры:
       - Фронтенд на порту `3000`
       - Бэкенд на порту `3001` (проксируется через Nginx)
     - Остановить работу контейнеров: 
       ```docker-compose down```
   - **Шаг 3**: Проверьте работу:
     - Фронтенд будет доступен по адресу ```http://localhost:3000```
     - Проверить API можно по адресу ```http://localhost:3001/data```
     
     
## **Как работает система**

- ### **Frontend (React)**:&#x20;
  - регулярно делает ```fetch``` запросы  к эндпоинту ```/data``` , обновляя  состояния устройств на визуальной части сайта
  - при взаимодействии с интерфейсом , фронтенд отправляет post запрос на бэкенд для изменения состояния соответствующего устройства
- ### **Backend (Flask)**:&#x20; 
обрабатывает ```get``` запросы c фронтенда, возвращая последние значения модулей, хранящиеся в переменной экземпляра класса ```MQTTHandler```, а при получении команд(post запросов) — публикует их с помощью класса ```MQTTHandler```, возвращая в ответе  на ```POST``` запрос  ```JSON``` с текущим статусом датчиков

- ### **MQTT\_Client**:&#x20;
  В основе лежит класс ```MQTTHandler``` — он инкапсулирует всю логику взаимодействия с ```MQTT```-протоколом и брокером: подключение, подписку на топики, обработку входящих сообщений и публикацию команд.

	- подписывается на указанные в конфигурации топики, принимает входящие сообщения от устройств и сохраняет актуальные данные в переменной экземпляра класса ```MQTTHandler``` для последующей передачи во Flask-приложение
  - также используется для публикации управляющих команд в нужные топики на MQTT-брокере 

## **Эндпоинты API**

   - ```POST /api/set-light-color``` — позволяет задать конкретный цвет RGB-подсветки
   - ```POST /api/toggle-module/<module_name>```\* — переключает состояние модуля (включение/выключение)
   - ```GET /data```\* — используется для получения текущего состояния всех компонентов системы
   - ```POST /api/setFanThreshold/<module_topic>```\* — задаёт цифровое значение для любого модуля (например, порог для  вентиляции(влажность) или климат-контроля(температура))

> \* Добавление новых функций модулей, выполняющих роль переключения(0/1), установки цифрового значения, получения показаний,   не требует изменений в бэкенде. Чтобы такая функция модуля / модуль стала доступна, достаточно указать его топик в переменной "MQTT\_TOPICS\_MONITORING\_CONDITION" файла .env в корневой директории  — и он будет автоматически доступен через универсальные эндпоинты без доработки кода со стороны бэкенда.
